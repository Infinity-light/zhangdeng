# 模组写法

编译器读的是带标题层级的 Markdown。规则只有三条：

1. `#` 是模组标题；`##` 是章节（元数据、宪法、场景、线索、NPC、真相层、触发器、结局、关键抉择、预设寻访者）；`###` 是章节里的一项；`####` 是一项里的子项（`可调查: 名称` 或 `知道: 标题`）。
2. `- 键: 值` 是字段。同一个键写多行就是多条（氛围、口头禅、条件……）。列表值用顿号或逗号分开。
3. 其余的段落是这一项的正文：场景的公开描述、可调查项的所见、NPC 会怎么说、触发器与结局的文字。

标题末尾的 `{#id}` 是编号，别处引用它。`>` 开头的行是给人看的备注，编译器跳过。

完整的例子就是 `modules/雾港来信.md`，建议直接照着改。

## 各章节的键

**元数据**　推荐人数、时代、地点、预计时长、规则包、恐怖尺度、内容提示、开场时间（HH:MM）、开场场景（场景 id）、开场白

**宪法**　基调（一条）、语气禁令（多条）、不可变事实（多条）；可选：路上 / 无回应 / 无人应答（各多条，离线演员在赶路、自由行动、对空发问时用的备用句——不写就用不带题材的中性句）

**场景 → ### 场景名 {#id}**　类型（主 / 侧）、别名、出口（场景 id）、在场（NPC id）、幕目标、氛围（多条）、加压氛围（多条）；正文 = 公开描述

**#### 可调查: 名称 {#id}**　关键词、明显（是）、需要（条件）、受阻（文字）、绕行检定（技能/难度）、绕行置flag、检定（技能/难度）、失败（文字）、失败态度（npc:±1）、奖励骰 / 惩罚骰（枚数）、定力（成功损失/失败损失；也可以写成 理智 / SAN / 理智检定）、阶段（看到它之后相位至少抬到：加压 / 对抗 / 揭示）、线索、载体、置flag、给物品、耗时（分钟）；正文 = 调查到的内容

**线索 → ### 线索名 {#C1}**　内容、所在、指向、关键（是 / 否）、给物品、载体（多条）

载体一行五段，用 `|` 分开：

```
- 载体: C3c | 一通打错的电话 | any | 事件 | 柜台上那部摇把电话响了……
- 载体: C7b | 魏长庚临到子时的一句话 | lighthouse | 事件@时间>=23:00 | ……
- 载体: C1a | 告示栏上的寻人启事 | dock | 可调查:board | （见告示栏）
```

依次是：载体编号、形式、地点（场景 id 或 `any`）、途径（`可调查:id` / `NPC:id` / `事件`，事件后面可以用 `@` 接一个条件）、事件文本。关键线索请至少写两种载体，其中至少一种是「事件」——那是玩家跑偏时导演能主动送过去的唯一形式。

**NPC → ### 姓名 {#id}**　别名、公开身份、真实身份、动机、常驻、初始态度、初始情绪、口吻、口头禅（多条）、常用词、禁用词、红线（多条）、招呼（多条）、闲谈（多条）、推脱（多条）、重复（多条，被问到已经说过的事时）；不会说话的人物加一行 `表达: 动作`，他的招呼、闲谈、推脱、交代都写成动作描写（例子见《枯井》的老秦）

**#### 知道: 标题 {#id}**　话题（关键词）、分享（随口 / 信任 / 绝不）、信任门槛、出示（线索 id）、给线索、载体、置flag、给物品；正文 = 他会怎么说（用他的口吻写）

**真相层**　幕后真相、存在、时间线（多条，`时间｜事件`）、不可泄露（多条，`编号 | 内容 | 关键词、关键词 | 解锁线索或永不`）

**触发器 → ### 名称 {#id}**　条件、效果（多条）、导演注；正文 = 公开文字。效果有四种：`flag:名=1`、`阶段:加压`（或 对抗 / 揭示）、`理智检定:全体:0/1d4`、`对手登场:名称|生命|战斗技能|伤害|护甲`（把一个对手放进规则台，之后的交手由掌灯人在规则台里主持）。写了别的，编译器会报「看不懂的效果」

**结局 → ### 名称 {#id}**　条件（多条，任一成立即达成）；正文 = 结局文本

**关键抉择 → ### 名称 {#id}**　需要、选项（多条，`id | 关键词 | 置的flag或- | 说明`）；可选：提示（一句世界内的话。这个抉择已经做得成、玩家却连着两轮没碰它时，掌灯人用它点一下；不写就用一句通用的）

**预设寻访者（也可以写成 预设调查员）→ ### 姓名 {#id}**　身份、属性（`力量 55、体质 60…` 或 `STR 50、CON 55…`）、技能（`救护 65、察觉 50…`）、背景、执念、恐惧源、关系、物品、AI口吻、AI误读 / AI退缩 / AI闲话 / AI不知道（多条）。写了 AI口吻 的那位，排座时默认交给 AI

## 通行写法都认

拿一份按通行的百分骰调查恐怖规则写的模组来改，检定点和理智损失不用重写：

| 你可以这样写 | 编译成 |
|---|---|
| `检定: 侦查/困难`　`检定: 困难侦查`　`检定: 侦查（困难）`　`检定: 侦查检定 困难` | 侦查，困难（技能值的一半） |
| `检定: 聆听，惩罚骰`　`检定: 心理学/普通/奖励骰2`　或另起一行 `- 惩罚骰: 1` | 多掷十位骰取劣 / 取优 |
| `检定: 力量/极难`　`检定: POW` | 直接掷属性 |
| `理智: 0/1d3`　`SAN: 1/1D6`　`理智检定: 1d2/1d8+1`　`定力: 0/1d2` | 成功损失 / 失败损失 |
| 触发器里 `效果: 理智检定:全体:1/1d6`（写 定力检定 / SAN检定 也行） | 全体过一次检定 |
| `属性: STR 50、CON 55、SIZ 60、DEX 60、APP 55、INT 70、POW 55、EDU 70` | 认缩写，也认中文名 |

技能名以模组所用规则包为准，别名互通（侦查 = 察觉、图书馆使用 = 查阅、心理学 = 识人、锁匠 = 机巧……）。规则包里没有的名字，审阅页会报出来，不会默默按别的值掷。

## 条件的写法

用 `&` 连接，全部成立才算：`flag:名`、`!flag:名`、`线索:C1`、`物品:名`、`场景:id`、`时间>=23:30`、`时间<22:00`。过了午夜接着往上写：`时间>=24:40`。

## 写的时候留意

- **事实写在原文里。** 调查所见、NPC 的交代、事件文本、结局都是原文投放，模型只写衔接。日期、数字、铭文放在这些地方不会走样。
- **「绝不」是真的绝不。** NPC 的「绝不分享」项不会进它的上下文，所以它连暗示都做不到——想让它欲言又止，把欲言又止写进「推脱」里。
- **不可泄露的关键词要具体。** 「深潜者」「钟舌」好过「变成了」「在水下」——太日常的词会误伤正常叙述。
- **每个场景多写几条氛围句。** 长团里叙述不重复靠它。
- **自由文本的模组**（没有按上面的格式写）也能导入，需要配了模型。编译器不让模型一口气写整份 spec，而是分四段各问一类问题（场景与可调查物 / 人物 / 线索与真相 / 定时事件与结局），模型只用名字互相指；编号、引用、载体、关键抉择和结局条件由代码组装，替模型补了什么、改了什么都列在审阅页最上面。用免费的 Flash 型号实测两份陌生的短模组，都是 0 处 error、不改就能开团，耗时 2–3 分钟（见 `docs/验收实测.md`）；抽取的细节仍然可能走样（比如把「在族长袖子里」读成「在供桌上」），请在审阅页核对后再点确认。
