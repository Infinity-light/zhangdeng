# 已知限制（一页）

这是 8 小时内做出来的一版。P0 闭环是通的，下面是哪些地方还是原型、哪些长团场景没有覆盖。

## 模型与文本

- 骰运差的时候，同一样东西的失败文字会重复（撬两次匣子是同一段话加一句「这一次的动静不小」）；几个人同时掉定力时症状是同一句。AI 同伴的接话有一半是复述刚才的描写，不会主动做事。这些是第 19 轮亲手玩时记下的，见 docs/调研与重做.md。

- **线上演示用的是免费的智谱 Flash 型号。** 它够快（多数轮 1–3 秒），但文笔一般，偶尔限流；限流或超时时这一段自动落回离线演员，日志里会记一笔。换成更强的模型只需要改 `.env`。
- **关键事实不交给模型写。** 调查所见、NPC 的交代、事件、结局都是模组原文投放，模型只写衔接叙述、接话、推脱、闲谈和 AI 寻访者的台词。这是为了零矛盾做的取舍，代价是模型的发挥空间小。
- **离线演员只是为了不花钱也能跑通闭环。** 它的文字全部来自模组里写好的句子，谈不上「扮演」。
- **模型写的衔接叙述里的小细节没有登记。** 气味、声音这类即兴不进状态库。闸门只拦得住几类明确的东西：未解锁的真相关键词、不在场的 NPC 名、材料外的数字、一批常见的「造物」名词（警长、地道、暗门……）。模型若用别的说法编出一个新东西，目前拦不住。
- **即兴事实的登记是半手动的。** 状态库有「已确立事实」这一栏，掌灯人控制台可以登记，登记后会进叙述层的事实卡；但没有做到「模型即兴 → 自动抽取 → 自动登记」。

## 导演层

- **意图识别以关键词规则为主，模型只做辅助。** 玩家的话里出现场景名、NPC 名或可调查项的关键词就按规则认；认不出时（配了模型的话）让模型在「此刻公开可见的选项」里选一个，选不出就按自由行动处理（不会被否决，但也不会触发调查）。反过来也会误认：实测里「对着井口喊：你是谁」被当成了再看一遍井口，而不是一次对空发问。
- **剧本测得好，不等于随口话接得好。** 让模型临场扮演玩家试玩（`tests/playtest.mjs`）之后补了几样：问句里只是带到地名的不算动身；开口先叫了人就是对他说话；同一件事再问一遍，掌灯人把上回的要点点出来；话里说的是已到手的线索就把它再给一遍；「四处看看」把此地的东西、人、去处数一遍；开口先叫同桌的人是桌上商量，不唤醒 NPC；话里说的是手里的东西而此地正要用它，就是去用它；再看查过的东西时带上回看到的头两句；动身要动词在前地名在后，或整句差不多就是地名；关键抉择做得成却没人碰时给一句世界内的「抉择提示」；此地没线可补时「指路」。关键抉择只认陈述，问句里带到抉择的说法不算做了决定。即便如此，每局仍有一部分话落进「没认出来」，只得到一句衔接；也还有认偏的：补送到手里的东西换了个叫法（「打开妇人塞给我的纸」）会被认成去看此地另一样相近的东西（磨盘上的黄纸），而不是重看刚到手的那条线索。
- **引擎只提醒、不代劳。** 试玩里免费 Flash 型号扮的玩家会原地打转（围着一个人反复问同一句、围着一样东西反复摸），补线、抉择提示、指路都说了它也不一定照做；引擎不会替玩家移动、替玩家做抉择，所以这样的玩家到不了结局，除非时间走到 spec 里的定时结局。八轮试玩里只有两局收团：一局是时间走到了定时结局，另一局是引擎把一句问话（「是封井的咒语？」）当成了做抉择——这处已改成关键抉择只认陈述、问句不算；没有一局是试玩员自己做出关键抉择收的团。真人玩家会不会卡在同样的地方，没有测过。
- **自由行动的后果只有叙述，没有机制。** 「我放火烧了牌馆」会得到一段叙述和时间流逝，但不会真的烧掉牌馆。
- **全队始终在同一个场景。** 没有做分头行动。
- **NPC 不会自己走动，主动行动只有一种。** NPC 的位置在状态库里，可以由控制台改，但没有日程。「NPC 主动行动」目前有三处：触发器、事件型载体，以及玩家跑偏而此地没有事件型载体时，在场又肯说的 NPC 会自己开口把线索交出来。NPC 不会主动找上门、不会跟踪、不会互相交谈。
- **相位判断是规则写死的**（线索进度、跑偏计数、时间、触发器），没有按玩家情绪动态调。

## 规则

- 已实现并有单元测试：技能检定、三档难度、顺势/逆势骰、孤注一掷、组合检定、对抗检定、定力检定、短时/长时/永久失序、攻击与闪避/反击、伤害与护甲、重伤与死亡判定、成长检定。
- **战斗是掌灯人手动主持的，不是自动的。** 控制台的「规则台」里可以让对手登场、排先攻、逐次点「寻访者攻击 / 它攻击·闪避 / 它攻击·反击」，骰子、伤害、护甲、重伤和昏迷都由引擎算并落库；但导演层不会自己主持战斗，玩家打字说「我打它」也不会自动进入战斗轮。模组可以在触发器里写「对手登场」把对手放上场，之后每一下交手仍然要掌灯人点。两份示例模组本身都不需要战斗。
- 规则台里的检定、暗骰、理智检定、对抗、成长检定同样是掌灯人手动点的；玩家席位没有「我要求过一次检定」的入口。
- 法术表、神话物品表只是数据，没有接效果。武器的弹药数、射程不参与计算。
- 自带两套规则包。`tongxing-d100` 没有做的：幸运值与燃运、信用评级的生活水平、全自动武器连射、追逐、技能的专攻分支（各类格斗 / 射击 / 外语只保留了一个总项）。
- 规则包目前能换的是数值、技能表、难度系数、各类表格；判定流程本身（比如换成骰池制）需要改 `rules.mjs`。

## 编译器

- **结构化 Markdown 是确定性解析，有充分测试；自由文本靠模型分段抽取，只实测过两份。** 用线上的免费 Flash 型号测了两份没按格式写的中文短模组（《枯井》自由文本版约 700 字、《停摆》约 1300 字），都得到 0 处 error、不改就能开团的 spec，耗时 100–190 秒。但抽取会丢细节、会读错位置（实测里出现过：把「藏在族长袖子里」读成放在供桌上；坏结局的两种触发方式只读出一种），所以审阅这一步不能省。更长的模组（超过 2.4 万字会被截断）、多章节的大模组没有测过。
- 自由文本抽出来的 spec 里，场景默认两两相通、都算主场景，没有「侧支地点」和「进入条件」；想要门锁、钥匙这类前置条件，需要在完整 JSON 里补。
- Word 文档（.docx）可以直接选进来（浏览器里读正文，标题样式转成标题层级；表格、图片、文本框里的字读不到）。PDF 和扫描件不支持，需要先把正文复制出来。
- 审阅页能直接改的字段是常用的那些（线索与载体、可调查项的检定与理智损失、NPC 的身份/口吻/红线、真相、宪法基调、元数据、规则包）；其余字段（进入条件、触发器、结局条件、关键抉择的说法）要在「完整 JSON」页里改。
- 线上的自由文本编译同一时间只跑一份（一次要调四段模型），撞上了会提示过一两分钟再试。

## 多人与安全

- 多人靠「席位链接 + 2.5 秒轮询」，不是实时推送。几个人同时出手会按到达顺序排队、一轮一轮处理（有单元测试）；没有做「按先攻轮流发言」这样的回合顺序。
- 席位凭证是链接里的随机串，没有账号体系。**不要把掌灯人的链接发给玩家。**
- X 卡做了「遮住上一段 + 随后三轮淡化」，没有做「倒回重写这一段」「跳过整个场景」的完整流程。内容分级只有「完整 / 全程淡化」两档。
- 线上服务最多保留 300 局团，超出后删最旧的。重要的团请及时导出存档。

## Replay

- 「如果当时选另一条」的可达结局是静态推算（按结局条件和当时的 flag、时间排除不可能的），不是真的往下模拟。
- 记录稿默认是按日志顺序拼接的。配了模型时可以在 Replay 页点「请模型润色成小说体」：模型一节一节改写，每一节都要过闸（不泄露未解锁的真相、不多出原文没有的数字和人名、不出戏），不过闸的那一节保留原文。润色的文笔取决于模型；闸门只拦得住上面这几类，模型若悄悄改了一句对白的意思，拦不住——所以原始记录始终附在后面。
- PDF 靠浏览器把 HTML 打印成 PDF，没有内置生成。

## 没有实测过的

- **解包工具**：Git Bash 自带的 unzip 会把包里的中文文件名（`modules/雾港来信.md` 等）解成乱码，测试会因此找不到模组；用系统自带的解压、7-Zip 或 Python 的 zipfile 没有这个问题。
- **真机手机**：手机端只在本机 Chrome 的触摸模拟里验过（390×844、360×640），没有上过真机。软键盘弹起后的布局、Safari 地址栏伸缩、刘海安全区都没有验。
- **声音好不好听**：全部是 WebAudio 现场合成，音色照着参数写的；走查用的是无头浏览器，只确认了不报错、静音开关会切，没有人耳听过。
- **好结局没有亲手玩出来过**：第 19 轮亲手玩的那一局落在坏结局「回信」；之后改了「点灯」那句话的归类，只做了单元测试，没有再完整玩一局。离线剧本长跑能走到好结局。
- **真人盲测辨认 NPC 口吻**：只做了机检（禁用词、交叉相似度），没有找人盲测。
- **2 小时真人长团**：剧本长跑是 54 轮、线上不到 5 分钟；另有一局线上按真实时间跑（每步间隔 50 秒，玩家由模型扮演），连续 71 分钟、72 轮，故事里的时间走到了定时结局就收团了，没有到两小时。没有真人坐满两小时。
- **两个真人在两台设备上同时玩**：接口层面按席位过滤已测，真实的双设备并发没有测。
- 许愿人说可以提供的测试模组、真实跑团 log 和验收用例清单，开工时没有拿到；剧透诱导用例是自己编的 12 条（`tests/cases-spoiler.json`）。
