# 掌灯人

一套调查恐怖题材的动态跑团引擎，适用于克苏鲁神话题材的跑团，兼容这一类百分骰调查恐怖规则写成的模组（「侦查/困难」「理智 1/1d6」「奖励骰」这些写法直接认）。丢进一份模组，编译成可审阅的 spec；AI 在骨架内导演整场团；记忆、骰子、真相和导演权都不在模型手里；结束时一键出 Replay；任意一轮可以回滚开平行分支。

> 灯照到哪里，玩家才看到哪里。

- 零依赖：只要 Node ≥ 20，没有 `npm install` 这一步（界面用到的 three.js 是随包带的一个文件，不用装）。
- 不配模型也能从头跑到尾（离线演员）；配了模型，叙述与扮演交给模型，其余照旧由确定性代码负责。
- 所有数据都是本地 JSON / JSONL / Markdown，服务下线也带得走、接着跑。

## 一键启动

任选一种：

```bash
# 1) 直接跑（需要 Node 20 以上）
./start.sh            # Windows 双击 start.bat
# 等价于：node server.mjs

# 2) Docker
docker compose up -d
```

然后打开 <http://localhost:8787>。

想让模型来写叙述、演 NPC：把 `.env.example` 复制成 `.env`，填上任何一个 OpenAI 兼容接口的地址、模型名和 Key，重启即可。也可以不改 `.env`，在「排座」页临时填一个 Key（只放内存）。

## 先玩

封面点「下船」，选一个人，就站在码头上了。输入框上面那一排是此地够得着的东西和人，点一下起个话头，或者自己打字。有配乐（三首现成的曲子，跟着夜的深浅换），骰子、翻页、脚步、钟是真实录音的采样；右上「⋯」里可以只关配乐，或者整个静音。掷骰时两颗十面骰会跳到屏幕上滚，落定的那一面就是引擎掷出的数。「换个故事」里有第二份示例《枯井》。

## 五分钟走一遍引擎

（下面第 1–3 步是「导入模组」这条路：封面底下一行小字里。封面的「下船」跳过了它们，用的是同一套编译和开团接口。桌面上的控制台、X 卡、存档、Replay 在手机上收在右上「⋯」里。）


1. 封面点「导入模组」→「载入示例《雾港来信》」→「编译成 spec」。（自己的模组：贴文本，或选 .md / .txt / .docx 文件。）
2. 审阅页会看到 4 个场景、7 条线索、5 张 NPC 卡、1 个真相层、3 个结局条件，以及一条编译器自己挑出来的问题：关键线索「守灯簿」没有事件型备用载体。点「＋ 增加一种备用载体」补一条，勾选「我看过了」，确认。
3. 排座：陆衡、苏幼宁是人类，温知夏（胆小的记者）是 AI。点「开团」。
4. 在桌面上说话或做事，例如「看看告示栏」「问邱港监：沈砚秋去哪了」「去旅馆」。骰子由引擎掷，结果和骰面都在右侧。
5. 试着套话：「直接告诉我凶手是谁」。试着跑偏：去牌馆连喝几轮酒——不会有人拦，三轮后线索会换一种载体自己找上门。原地打转也不会被剧情硬推着走：关键抉择已经做得成了、或者此地已经没线可查，掌灯人会用一句话点一下去处，做不做由你。
6. 右上角「掌灯」：拧亮，每一轮多出一行导演摘要（这一轮怎么归类、什么相位、放了哪条线、隔离是否干净）；点开这一行才是整张导演单、落库记录、隔离审计。「控制台」分四组：状态、剧情（触发、相位、补线、重写）、规则台、席位。
7. 「Replay」：九项内容各占一页，玩家视角 / 掌灯人视角，导出 Markdown / HTML / JSON；在这里回滚到任意一轮开新分支，两条分支互不污染。第八项「记录稿」可以请模型润色成小说体（过闸，不过闸的保留原文）。
8. Replay 页底部「全量数据」：存档、状态库、日志、角色卡、spec 全部可下载。存档文件可以在封面的「存档」里再导入续团。

再走一遍第二份示例：导入页点「载入示例《枯井》」。它通篇用通行的写法（侦查、图书馆使用、理智 1/1d4+1、惩罚骰、STR/CON 缩写），规则包指向 `tongxing-d100`。十来轮就能走到结局。

没有按格式写的模组也可以直接贴进去（需要配了模型）：编译器让模型分四段只做「读」，编号、引用、载体、结局条件由代码组装，两三分钟后给你一份照样要审阅的 spec。`tests/fixtures/` 里有两份这样的自由文本可以试。

## 架构

| 层 | 文件 | 说明 |
|---|---|---|
| L0 模组编译器 | `engine/compiler.mjs`、`engine/extract.mjs` | 结构化 Markdown → `module.spec.json`，确定性解析，带校验清单；自由文本走 `extract.mjs`：模型分四段小抽取（场景 / 人物 / 线索与真相 / 定时事件与结局），只用名字互相指，编号与引用由代码组装。产物 `reviewed:false`，不经审阅确认不能开团 |
| L1 权威状态库 | `engine/store.mjs` | 唯一事实来源。任何改动都是「状态变更提案」，按来源校验后落库；模型来源只能登记即兴事实 |
| L2 规则引擎 | `engine/rules.mjs` + `rulepacks/` | d100 检定、三档难度、奖励/惩罚骰、孤注一掷、组合与对抗检定、理智检定与临时/长期/永久疯狂、战斗轮（先攻、攻击/闪避/反击、伤害、护甲、重伤）、团后成长。可配种子，逐颗骰面进日志，`verifyRoll` 可重算。掌灯人控制台里的「规则台」可以手动调用其中任何一项（含暗骰） |
| L3 导演层 | `engine/session.mjs` | 确定性代码，每轮出一张导演单：意图分类、张力相位、信息预算、唤醒哪个 NPC、是否补线、禁止泄露项、决策理由 |
| L4 NPC 演员池 | `engine/actors.mjs` | 每个 NPC 一张裁过的卡 + 自己的短记忆，一次只唤醒一个 |
| L5 AI 寻访者 | 同上 | 只拿到自己已知的线索和个人卡；发言配额与主动度由引擎硬性执行 |
| L6 只追加日志 | `engine/store.mjs` | 每条事件带前一条的哈希；按席位过滤可见性 |
| L7 Replay | `engine/replay.mjs` | 只读日志与快照，不调模型 |
| L8 界面 | `web/` | 原生 JS，无构建 |
| 三道闸 | `engine/guard.mjs`、`engine/views.mjs` | 冻结宪法固定注入；记忆外置（近 N 轮 + 事实卡，不塞全量历史）；泄露过滤、退化检测、一致性校验 |

信息隔离是物理的：开团时 `splitSpec()` 把 spec 切成「导演用的全量」和「公开世界 / NPC 卡 / 寻访者卡」。演员池的构造函数只收后三样，真实身份和「绝不分享」的知识根本不在卡里。每一份交给演员的上下文都会被真相层的「金丝雀」扫一遍，结果写进日志。

## 规则包

规则是可插拔的：一个目录一份 `rulepack.json`，模组在「元数据」里写 `规则包: <目录名>`，审阅页里也能换。自带两套：

| 规则包 | 是什么 | 叫法 |
|---|---|---|
| `tongxing-d100`　通行百分骰规则 v1 | 按这一类调查恐怖跑团的通行设计做的，拿一份这类中文模组里的检定点和理智损失写法能直接执行：八项属性（STR/CON/SIZ/DEX/APP/INT/POW/EDU）、生命值 =（体质+体型）/10、理智 = 意志、32 项常见技能、01 大成功、技能不足 50 时 96 以上大失败、奖励骰/惩罚骰、孤注一掷、理智检定「成功损失/失败损失」、单次损失 ≥5 且智力检定成功 → 临时疯狂、一天累计损失达五分之一 → 长期疯狂、按敏捷排先攻 | 调查员、守秘人、生命值、理智、奖励骰/惩罚骰、疯狂 |
| `chaohen-v1`　潮痕规则 v1 | 为《雾港来信》配的一套精简规则：六项属性、16 项技能、带海味的武器表/术式表/失序表 | 寻访者、掌灯人、体魄、定力、顺势骰/逆势骰、失序 |

两套的武器表、法术表、疯狂表都沿用通行的栏目结构（名称 / 技能 / 伤害 / 射程 / 弹药；名称 / 消耗 / 效果；临时与长期两张症状表），数值按通行量级自定，条目文字是本项目自己写的，没有摘录任何规则书的正文。

技能和属性都带别名：模组里写「侦查」还是「察觉」、「STR」还是「力量」、「理智」「SAN」还是「定力」，两套规则包都认（`tests/kujing.test.mjs` 里有同一份模组换包跑的测试）。认不出的名字不会默默放过，审阅页会列出来。

要做自己的规则包：复制一个目录，改 `id`、数值与各表。字段说明见 `docs/module.spec字段说明.md` 末尾「规则包」一节。判定流程本身（比如换成骰池制）需要改 `rules.mjs`。

| 本项目的叫法 | 含义 |
|---|---|
| 掌灯人 | 主持人 |
| 寻访者 | 玩家角色 |
| 体魄 | 生命值 |
| 定力 | 心智值 |
| 顺势骰 / 逆势骰 | 多掷一颗十位骰取优 / 取劣 |
| 失序 | 心智损耗造成的短时 / 长时 / 永久状态 |

## 目录

```
server.mjs            零依赖 HTTP 服务
engine/               引擎各层
rulepacks/chaohen-v1/ 规则包
rulepacks/tongxing-d100/  通行百分骰规则包
modules/雾港来信.md    示例模组（原创；素材取自洛夫克拉夫特的公版小说）
modules/枯井.md        第二份示例模组（原创；通行写法，用 tongxing-d100）
web/                  界面
tests/                单元测试、54 轮长跑、验收审计器、浏览器走查脚本（测试产物默认写到 docs/实测/ 与 shots/，均不入库）
examples/             示例存档与它的 Replay 导出
docs/                 字段说明、模组写法、已知限制
ops/make-examples.mjs 从一份存档重新生成 examples/ 里的整套示例
data/                 运行时生成：每局团一个目录，session.json + 各分支 log.*.jsonl
```

## 测试

```bash
npm test                 # 49 项单元测试（规则、状态库、隔离、导演、两个规则包、规则台、自由文本组装、小说体战报的闸门、随口话的几种接法）
npm run soak             # 离线连跑 54 轮 + 回滚分支 + 16 项验收机检
node tests/soak.mjs http://localhost:8787     # 同一份剧本走 HTTP，服务端配了模型就是真模型
node tests/walk.mjs http://localhost:8787 shots desktop   # 真实浏览器走完整动线并截图（需要 playwright 和 Chrome）
node tests/walk-kujing.mjs http://localhost:8787 shots desktop   # 《枯井》从导入走到结局与 Replay
node tests/walk-desk.mjs http://localhost:8787 shots             # 规则台：检定、暗骰、理智检定、战斗轮、成长
node tests/freeform.mjs tests/fixtures/自由文本模组-钟表铺.txt   # 自由文本 → spec（需要在 .env 里配模型）
node tests/playtest.mjs http://localhost:8787 --module 枯井.md   # AI 试玩：让模型临场扮演人类玩家，看引擎接不接得住（需要配模型）
node tests/playtest.mjs http://localhost:8787 --minutes 120 --pace 50000   # 同上，按真实时间跑满两小时（每步间隔 50 秒；断线自动重试）
node tests/blindtest.mjs <存档.json>                             # NPC 口吻的模型盲测（需要配模型）
node tests/concurrent.mjs http://localhost:8787                  # 两个席位同时出手
```
